## 1. 这份工作台从哪来

本工作台服务《数据现状分析工作方案》的 **P0→P7 / 29 表框架**，主线是 **字段级引用事实（表 15）**。

背景约束（决定了“先摸清再用”的路径）：

- 缺少完整原始库设计文档，主要输入是 **源代码 + 金仓 DMP**；
- 业务表混乱，重构不能“直接建新库”，需要先逆向还原再用关系；
- 最终能力会进入 **数据中台的元数据 / 血缘**，但当前先用独立工作台把问题跑通。

**本工作台不是：**

- 业务办理系统；
- 生产数据中台供数平台；
- 全息综合展示（全息面向业务用户，中台面向专业人员与系统）。

**本工作台是：**

- 重构前的影响分析与闸门工具；
- 回答“有什么字段、谁在用、能不能改”；
- 向中台导出元数据 / 血缘候选的前置形态。

## 3. 探索页只回答两个问题

最初按“正向 / 反向钻取”做了双视角：

1. 系统 → 模块 → 接口 → 库 → 表 → 字段  
2. 库 → 表 → 字段 → 系统 → 模块 → 接口  

并曾用三栏分栏展示“选中后的下一层集合”。

评审后收敛为 **两个用户问题**（避免“正/反向”术语干扰）：

### 问题一：字段被谁用

> 一张表里的某个字段，都被哪些 **系统 / 模块 / 接口** 引用？

路径：选库 → 选表 → 看字段清单（引用摘要）→ 点字段看调用方。

### 问题二：接口用了什么

> 某个系统的模块 / 接口，用了哪些 **库 / 表 / 字段**？

路径：选系统 →（可选）模块 →（可选）接口 → 看触达面。

顶栏用两个问题入口切换，不再用“正向 / 反向”作为主叙事。

## 4. 问题一的交互痛点（已反馈）

### 现象

字段详情底部用 **系统 | 模块 | 接口** 三栏并列：

- 默认未选时，三栏各自铺开 **全部数据**；
- 模块、接口跨系统混在一起；
- 看不出“哪个接口属于哪个模块、哪个模块属于哪个系统”。

### 用户原话（要点）

> 默认不选时三栏都显示全部数据，都不知道哪个是对应哪个。  
> 三栏展示不是想要的那种。

### 中间尝试（已否决作为终态）

改为“逐级点选才展开下一栏”（未选系统则模块/接口为空）。  
能缓解对应关系，但 **三栏并列本身仍不符合预期**。

---

## 5. 当前设计思路（方案 A：引用树）

### 5.1 原则

用 **嵌套树** 表达父子归属，而不是并排三栏：

```text
字段 PROJECT_CODE
├─ 系统：全息平台
│  └─ 模块：项目全景
│     └─ 接口：…  (API · SELECT)
└─ 系统：公共服务平台
   └─ 模块：项目台账
      └─ 接口：…  (API · INSERT)
```

### 5.2 交互要点

| 点 | 说明 |
|---|---|
| 默认展开 | 打开字段后整树展开，一眼看清归属 |
| 可折叠 | 系统 / 模块节点可折叠，控制信息量 |
| 层级标签 | 行内标明「系统 / 模块 / 接口」 |
| 叶子动作 | 点接口 → 跳到问题二，带上系统/模块/接口上下文 |
| 空态 | 无引用时明确“零命中”，不画空栏 |

### 5.3 为什么比三栏更合适

- **归属关系是树，不是平行列表**；
- 不需要先点选才能理解对应关系；
- 与“字段被谁用”的认知顺序一致：谁（系统）→ 哪块业务（模块）→ 哪个入口（接口）。

### 5.4 可选对照方案（未定）

若树在引用很多时显得长，可再设计：

- **方案 B**：按系统分组的折叠摘要表（系统一行，展开才见模块/接口）；
- **方案 C**：路径列表（每行一条完整路径 `系统 / 模块 / 接口`，可筛选）。

定稿前建议在 Figma 里并排放，选一种主形态。

## 6. 问题二的现状（暂保持）

问题二仍用左侧级联（系统 → 模块 → 接口）+ 右侧触达面：

- 未选模块：系统级全部触达字段；
- 选模块未选接口：模块级汇总；
- 选接口：库 | 表 | 字段 分栏。

这里的三栏是 **同一接口下的库表字段分解**，父子关系相对清晰；若后续也觉得乱，可同样改为树或路径列表，与问题一对齐。

## 7. 与数据中台 / 全息的边界（讨论共识）

```text
业务系统（规划 / 执行 / 评估 / …）
        ↓ 接入与交换
数据中台（元数据 · 标准 · 质量 · 血缘 · 服务）  ← 本工作台将来并入「元数据/血缘」
        ↓ 数据服务
全息平台及其它应用（面向业务用户的综合展示）
```

- **全息**：面向业务用户的综合应用，不替代专业办理；
- **中台**：面向专业人员与系统的数据能力；
- **本工作台**：重构期摸底与影响分析；成熟后能力并入中台血缘，而不是长期平行系统。

## 9. 设计协作流程（约定）
